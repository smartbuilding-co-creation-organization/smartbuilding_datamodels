# AGENTS.md

## 1. Repository Overview

- **Purpose**: Manage a LinkML-based smart building ontology and publish the derived OWL, SHACL, JSON Schema, and MkDocs outputs for the Smart Building Co-creation Organization standard discussions.【F:README.md†L1-L37】
- **Data flow**: Schema edits live in `schema/building_model_shacl.yaml` (SHACL/JSON Schema/Docs) and `schema/building_model_owl.yaml` (OWL); LinkML generates RDF/JSON artifacts into `output/`, and `gen-doc`/MkDocs render the schema reference under `docs/reference/`.【F:README.md†L6-L25】【F:Makefile†L1-L30】
- **Schema focus**: `schema/building_model_shacl.yaml` defines prefixes, enums, custom types, and the cardinal hierarchy (Site → Building → Level → Space → Equipment → Point) that drives SHACL/Docs outputs; keep it synced with the documentation pages.【F:README.md†L38-L44】
- **Documentation structure**: `docs/index.md` is a hand-authored landing page (edit it directly); `docs/reference/` (class/slot/enum/type pages) is generated by `gen-doc` — treat it as a derived artifact; `docs/guide/` is synced automatically from smartbuilding_documents via `scripts/register_documents_guide.py` — do not hand-edit it either.
- **Dependencies/environment**: Python packages are pinned in `requirements.txt` (LinkML, LinkML runtime, MkDocs + Material, PySHACL) and consumed via the provided `Makefile` targets or the Quick Start commands in README.【F:requirements.txt†L1-L5】【F:Makefile†L1-L30】【F:README.md†L13-L25】

## 2. Operating Principles

- **Single source of truth**: Modify `schema/building_model_shacl.yaml` for SHACL/JSON Schema/Docs changes and `schema/building_model_owl.yaml` for OWL changes; run the prescribed LinkML commands to regenerate outputs so everything stays in lockstep.【F:README.md†L17-L25】【F:Makefile†L1-L30】
- **SHACL generation**: The LinkML CLI currently does not accept `--include-range-class-descendants` or `--schema`/`--output`, so list descendant classes explicitly in the schema (e.g., include `PointExt`/`EquipmentExt`) and run `linkml generate shacl --non-closed --suffix Shape schema/building_model_shacl.yaml > output/building_model.shacl.ttl` to keep shapes open, append `Shape`, and redirect stdout into the SHACL file.【F:README.md†L17-L32】
- **Docs & preview**: The `gen-doc --directory docs/reference --template-directory templates/docgen schema/building_model_shacl.yaml` command feeds MkDocs (`mkdocs serve`, `mkdocs build`, `mkdocs gh-deploy`) so reader-friendly docs always match the schema surface. `templates/docgen/` holds locally-patched copies of LinkML's default docgen Jinja2 templates (fixes for MkDocs-material rendering — see git history for `class.md.jinja2`/`enum.md.jinja2`/`slot.md.jinja2`/`type.md.jinja2`/`subset.md.jinja2`); if `pip install -r requirements.txt` bumps the `linkml` version, re-diff these against the newly installed package's own templates and re-apply the patch if upstream changed.【F:README.md†L22-L28】【F:Makefile†L14-L28】

- **Schema sync (OWL/SHACL)**: Keep `schema/building_model_owl.yaml` and `schema/building_model_shacl.yaml` synchronized to reflect the same content. Differences are limited to OWL vs SHACL output requirements, and `any_of` / `SPACE_UNION` usage should be confined to that scope.【F:schema/building_model_shacl.yaml†L528-L541】

## 3. Safety & Security Guardrails

- **No secrets**: This repo has no `.env` files; avoid adding secrets or environment configs—everything is driven by static schema/docs and the Python toolkit.【F:README.md†L1-L44】
- **Generated artifacts**: Do not edit `output/` or `docs/reference/` files by hand; regenerate them via the LinkML/MkDocs commands whenever schema or doc content changes to keep provenance clear. `docs/guide/` is likewise machine-synced (from smartbuilding_documents) — do not hand-edit. `docs/index.md` is the one exception: it's a hand-authored landing page.【F:README.md†L6-L28】【F:Makefile†L14-L28】
- **Immutable schema contracts**: Changes that alter class inheritance, slot definitions, or enumerations must update the schema, regenerate outputs, and mention downstream impact (SHACL/OWL/JSON Schema) because those definitions feed every artifact.【F:README.md†L17-L44】

## 4. Tooling & Commands

- **Environment setup**: `python -m venv .venv && source .venv/bin/activate` then `pip install -r requirements.txt` (these are also the first steps in the README Quick Start).【F:README.md†L13-L16】
- **LinkML generation**:
  - `linkml generate owl --metadata-profile rdfs schema/building_model_owl.yaml -f ttl > output/building_model.owl.ttl`
  - `linkml generate shacl --non-closed --suffix Shape schema/building_model_shacl.yaml > output/building_model.shacl.ttl`
  - `linkml generate json-schema schema/building_model_shacl.yaml > output/building_model.schema.json`
  - `gen-doc --directory docs/reference --template-directory templates/docgen schema/building_model_shacl.yaml`
  (the exact command list is reified in both the README and the `gen` Makefile target).【F:README.md†L17-L24】【F:Makefile†L14-L19】
- **RDF validation**: `make validate` runs `scripts/generate_validation_ttl.py` (converts YAML cases to RDF) and `scripts/validate_rdf.py` (OWL inference + SHACL checks) against cases in `sample/validation/cases.yaml`. Add new cases there whenever schema constraints change.【F:Makefile†L26-L28】【F:README.md†L27-L39】
- **Docs/preview/deploy**: `gen-doc --directory docs/reference --template-directory templates/docgen schema/building_model_shacl.yaml`, `mkdocs serve`, `mkdocs build`, and `mkdocs gh-deploy --force --clean` capture the workflow for running and publishing documentation; `Makefile` exposes shorthand targets (`docs`, `serve`, `deploy`, `clean`).【F:README.md†L22-L25】【F:Makefile†L14-L30】
- **Cleanup**: `make clean` removes the `site/` directory generated by MkDocs (`rm -rf site`).【F:Makefile†L29-L30】

## 5. Change Workflow

- **Plan, update, regenerate**: For any change that touches the schema, add/update docs if needed, rerun the relevant LinkML commands, then rerun MkDocs build/serve so the published docs align with the new schema state.【F:README.md†L17-L25】【F:docs/index.md†L1-L167】
- **CI expectations**: The GitHub Actions workflow (documented in the README) regenerates every artifact on pushes to `main`, so keep local runs consistent with the scripted commands; failing builds typically signal mismatched schema/docs outputs.【F:README.md†L32-L37】
- **Ownership**: The LinkML schema drives every generated file, so keep schema edits minimal, document the reason for each change, and include the regeneration commands in any PR description or README update.【F:README.md†L38-L44】

## 6. MUST NOT List

- MUST NOT commit manual edits to `output/*.ttl` or `docs/*.md` without first regenerating them from the schema; treat these files as build artifacts.【F:README.md†L6-L25】【F:Makefile†L14-L28】
- MUST NOT skip enumerating descendants such as `PointExt`/`EquipmentExt` in the schema and using `--non-closed --suffix Shape` with stdout redirection so the SHACL output stays consistent with the documented workflow.【F:README.md†L17-L32】
- MUST NOT forget to mention any schema change’s downstream impact on OWL/SHACL/JSON Schema/docs in GitHub PR notes so reviewers know why regenerations were required.【F:README.md†L17-L44】

## 7. Contributing Compliance (from CONTRIBUTING.md)

- **Required tooling**: Use Python 3.11+ and the latest Git; install dependencies with `pip install -r requirements.txt` inside a virtual environment.
- **GitHub Flow**: `main` is the single source of truth; create `feature/...` or `fix/...` branches and open PRs back to `main`.
- **Schema files**: Edit `schema/building_model_owl.yaml` for OWL changes and `schema/building_model_shacl.yaml` for SHACL / JSON Schema / Docs changes; keep both in sync for class and slot definitions.
- **Naming rules**: Class names use `PascalCase`, slot names use `camelCase`, schema filenames use `snake_case.yaml`.
- **Descriptions required**: Every class, slot, and enum value must have an English `description`.
- **Regenerate after edits**: Run `make gen` to update `output/` and `docs/` before committing; never hand-edit generated files.
- **Validation**: Run `make validate` (Python-based OWL inference + SHACL) before opening a PR. Add new cases to `sample/validation/cases.yaml` when introducing new constraints.
- **Backward compatibility**: Avoid removing slots/classes, changing slot ranges, or adding `required: true` constraints without explicit `BREAKING CHANGE:` notes.
- **Commit format**: Use Conventional Commits (`feat`, `fix`, `docs`, `refactor`) and include `BREAKING CHANGE:` notes when needed.
- **PR checklist**: Confirm `make validate` passes, `output/` and `docs/` are regenerated, descriptions are present, and the change is non-breaking (or marked as breaking).
- **Release expectations**: Merges to `main` trigger automated artifact generation and GitHub Pages deployment via GitHub Actions.
