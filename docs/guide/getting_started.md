# スマートビル・オントロジー入門ガイド

> 初めてスマートビルや建物データ標準を学ぶ方のための入門ドキュメントです。  
> 事前知識は不要です。まずはこのドキュメントを通読してください。

本ガイドは3つのパートで構成されています。まず**概念編**でスマートビルに共通する普遍的な考え方を説明し、次に**実装例編**でセンサー・設備をネットワークにつなぐ一般的な実装方法を紹介し、最後に**プロジェクト編**で本プロジェクト（SBCO）が具体的にどのような定義・ツール・運用でこれらを扱っているかを説明します。

---

## 概念編

### 1. スマートビルとは

スマートビルとは、**快適性・省エネ・安全性などを向上させて施設の価値を高めるために、情報処理技術やロボット技術などの先進技術を活用する施設**のことです。ここでいう「施設」とは、建物本体だけでなく、出入り口・駐車場・庭園なども含めた「何らかの目的をもって設置した建物および設備」全体を指します。

スマートビルでは、温度・湿度・照度・消費電力など多数のセンサーからのデータをリアルタイムに収集・活用し、例えば以下のようなことが実現されます：

- 各部屋の温度・CO2濃度・在室状況を自動モニタリング
- 在室者がいない会議室の空調・照明を自動オフ
- 設備の異常をデータから事前に検知（予防保全）
- エネルギー使用量の見える化と最適制御

これらを実現するためには、**多数の機器・センサーからのデータを統一的に扱うための仕組み**が必要です。そして、その仕組みが社会に幅広く実装されるためには、多数のセンサーから受け取るデータが**共通の約束事に基づいて生成されている**必要があります。それが本ガイドがこれから説明する「ポイント」「データモデル」「オントロジー」であり、それらを本プロジェクトでどう具体化しているかが「ポイントリスト」です。

#### 正式な定義について

上記は初学者向けに**分かりやすさを優先した表現**であり、公式な定義文ではありません。国内におけるスマートビルの定義は、IPA（独立行政法人情報処理推進機構）デジタルアーキテクチャ・デザインセンター（DADC）のスマートビルプロジェクトが「スマートビル総合ガイドライン」（2023年4月公開）で提案しています。同ガイドラインは、スマートビルの定義に加えて、社会要素としてスマートビルが担うべき機能、従来のビルとの比較、設計原則と実装方針などを示しています。

正確な定義を確認する場合は、以下の一次情報を参照してください。

- [スマートビル総合ガイドライン（PDF）](https://www.ipa.go.jp/digital/architecture/Individual-link/ps6vr70000016bsc-att/smartbuilding_comprehensive_guideline.pdf) — IPA/DADC スマートビルプロジェクト
- [スマートビルガイドライン（IPA 公開ページ）](https://www.ipa.go.jp/digital/architecture/guidelines/smartbuilding-guideline.html) — 総合／システムアーキテクチャ／構築・運用の各ガイドライン一式

### 2. 「ポイント」とは

スマートビルの世界では、設備やセンサーなど、**データを生み出す出力源**のひとつひとつを**「ポイント（Point）」**と呼びます。ポイントが出力するデータには、以下のような種類があります。

| 区分 | 英語名 | 説明 | 例 |
|------|--------|------|----|
| 計測 | Measurement | センサーが測定した値（読み取り専用） | 室温: 24.5℃ |
| 計量 | Metering | 累積値の計測 | 電力量: 1,234 kWh |
| 状態 | Status | 機器の稼働状態（読み取り専用） | ポンプ: 運転中 |
| 設定 | Setpoint | 目標値の設定 | 設定温度: 26℃ |
| 制御 | Command | 機器への指令（書き込み可能） | エアコン: オン |
| 警報 | Alarm | 異常・アラームの通知 | 高温警報: 発生 |

一般的な施設には数百〜数千のポイントが存在します。これらポイントを一覧化したものが「ポイントリスト」であり、詳しくはプロジェクト編で説明します。

### 3. データモデル・オントロジーとは

センサーやポイントの情報を単に列挙しただけでは、コンピュータには「温度センサー」と「温度計」が同じものなのか、「3F」と「3階」が同じ場所なのかを判断できません。この課題を解決するために使われる一般的な概念が「データモデル」と「オントロジー」です。

**データモデル**とは、機器・空間・ポイント間の**関係と意味を機械が理解できる形式で定義したもの**を指します。

**オントロジー（Ontology）**とは、「建物とはどんな概念か」「設備と空間はどう関係するか」を**辞書＋文法のように形式的に定義した知識体系**を指します。

| 比喩 | 実際の役割 |
|------|-----------|
| 語彙（辞書） | `Building`（建物）`Equipment`（設備）`Point`（ポイント）の定義 |
| 文法（関係） | 「建物はフロアを持つ」「設備はポイントを持つ」というルール |
| 推論 | CO2センサーはセンサーの一種 → センサーは計測ポイントを持つはず、と推論できる |

これらは業界・プロジェクトによって指す範囲や粒度が異なる言葉です。**本ガイドおよび本プロジェクトでは、以上の意味でこれらの用語を使っています**。本プロジェクトにおける具体的なデータモデル・オントロジーの実装については、プロジェクト編で説明します。

## 実装例編

### 4. 施設における設備・センサーの実装例

ここからは概念の説明ではなく、施設内の設備・センサーを実際にネットワークへつなぐ際の**一般的な実装例**を紹介します。本プロジェクト固有の話ではなく、業界で広く使われている技術・パターンの解説です。

#### ゲートウェイとは

施設内に設置されたセンサーや設備機器は、直接インターネットにつながっていないことがほとんどです。**ゲートウェイ（Gateway）**は、これらの機器とビルOSクラウドをつなぐ中継装置です。

```
[温度センサー] ─── BACnet ───→ [ゲートウェイ GW001] ─── インターネット ───→ [ビルOS クラウド]
```

#### BACnetとは

**BACnet（Building Automation and Control Networks）**は、空調・照明・防災設備などの建物設備を制御・監視するために広く使われている通信プロトコル（ASHRAE規格）です。施設内の多くの機器がBACnetで通信しているため、後述するポイントリストにはBACnet固有のフィールド（`device_id_bacnet`、`object_type_bacnet`など）が含まれています。

#### その他の接続形態

すべての設備がBACnet経由でゲートウェイに接続されるわけではありません。実装にあたっては、以下のようなケースも考慮が必要です。

- エレベーターやシャッターなどのリモート制御設備は、BACnetではなく**メーカー個別仕様**で外部の監視センターに直接接続されるケースがある
- 電力情報は、上記の制御系ネットワークとは**別系統**（スマートメーターや電力量計の専用回線など）で収集されるケースがある

> ゲートウェイとビルOSの参考実装（リファレンス実装）は、後述の「6. 本プロジェクトの運用」を参照してください。

## プロジェクト編：本プロジェクトにおける定義と運用

ここからは、概念編・実装例編で説明した一般的な考え方を、本プロジェクト（SBCO）が具体的にどう定義し、どのようなツール・運用で扱っているかを説明します。

### 5. ポイントリストとは（本プロジェクトの実装）

**ポイントリストとは、施設内にあるすべてのポイントを一覧化した「カタログ」**です。センサーや設備そのものの情報は、本来はメーカー情報・機種・設置場所・保守作業履歴といった多様な概念がリンクされた構造を持ち、CSVのような固定的なカラム構造だけでは表現しきれません。

**本プロジェクトでは、そのカタログを目的に合わせて抽出したサブセットとして、CSV形式でポイントリストを定義・作成します。** CSVの各行がひとつのポイントに対応し、各ポイントについて以下の情報を記録します。

```
どの建物・部屋に ──→ site / building / floor / installation_area
どの機器が      ──→ device_id / device_name / device_type
どんな値を      ──→ point_type / unit / max_pres_value / min_pres_value
どう提供するか  ──→ point_specification / writable / interval
どのゲートウェイ経由で ──→ gateway_id / local_id
```

詳細なフィールド定義は [pointlist.md](pointlist.md) を、記入例は [pointlist_sample.md](pointlist_sample.md) を参照してください。

CSV形式のポイントリストは人間には読みやすい一方、そのままではコンピュータが意味を解釈できません。そこで本プロジェクトでは、国際標準の **[Brick Schema](https://brickschema.org/)** と **[RealEstateCore (REC)](https://www.realestatecore.io/)** を基礎として、スマートビルディング共創機構（SBCO）独自の拡張クラス（`EquipmentExt`、`PointExt`）を定義した**データモデル・オントロジー**を用意しています。ポイントリスト（CSV）は、このデータモデルへ変換されることで、機械が意味を理解できる形式になります。

### 6. 本プロジェクトの運用：2つのリポジトリと公開方針

本プロジェクトは、ポイントリスト作成からデータモデル生成までの一連の流れをオープンに開発・公開しており、以下の2つの公開リポジトリで構成されています。

```
smartbuilding_datamodel_builder/ ← CSVエディタ＆バリデータ（Webアプリ）
smartbuilding_datamodels/        ← オントロジー定義 + RDF/JSON Schema 生成（本ガイドの公開元）
```

いずれも GitHub 上で公開されており、誰でもソースコードを参照・利用できます。

#### データフロー

```
① ポイントリスト作成
   pointlist.md のフォーマットに従ってCSVを手作成、またはBMSから出力
         ↓
② builder Webアプリでインポート・検証・編集
   ブラウザ上でツリー表示を確認し、バリデーションエラーを修正
         ↓
③ RDF / JSON-LD / YAML などにエクスポート
         ↓
④ ビルOSプラットフォームへ投入
   datamodels のオントロジーに基づいて意味付けされたデータとして管理
         ↓
⑤ デジタルツイン構築・アプリ活用
   モニタリング・遠隔制御・AI分析・エネルギー最適化
```

#### smartbuilding_datamodel_builder（CSVエディタ）

ポイントリストCSVをブラウザ上で読み込み、編集・バリデーション・エクスポートができるWebアプリです。

🔧 **[デモを試す（GitHub Pages）](https://smartbuilding-co-creation-organization.github.io/smartbuilding_datamodel_builder/)** ・
[ソースコード](https://github.com/smartbuilding-co-creation-organization/smartbuilding_datamodel_builder)

- `pnpm install && pnpm dev` でローカル起動（ポート 5173）
- サンプルCSVを読み込むと `Site → Building → Floor → Room → Device → Point` の階層ツリーが表示される
- 必須フィールド欠落・参照エラーなどを自動検出
- CSV / JSON / RDF(Turtle) / YAML / JSON-LD でエクスポート可能

#### smartbuilding_datamodels（オントロジー定義）

[LinkML](https://linkml.io/) という仕様記述言語で書かれたオントロジーから、OWL・SHACL・JSON Schema を自動生成するリポジトリです。

- `schema/building_model_shacl.yaml` がメインの定義ファイル
- `output/` 以下に生成済みの RDF/Turtle・SHACL・JSON Schema が含まれる
- GitHub Actions により push のたびに自動生成・ドキュメント更新

#### 参考実装：ビルOS・ゲートウェイ

上記2リポジトリは「ポイントリスト作成 〜 データモデル生成」までを担いますが、その先の「④ ビルOSプラットフォームへ投入」「ゲートウェイでの中継」に対応する参考実装（リファレンス実装）として、以下のOSSプロジェクトが公開されています。SBCO自身のリポジトリではありませんが、データフロー全体を実際に動かして確認したい場合の入り口として参照してください。

- **[gutp-building-os-ri](https://github.com/gutp-bim/gutp-building-os-ri)** — ビルOSの参考実装。datamodels のオントロジーに基づく意味付けデータを受け入れ、デジタルツインとして管理する側の実装例
- **[nexus-gateway](https://github.com/gutp-bim/nexus-gateway)** — ゲートウェイの参考実装。BACnetなどで収集したポイントデータをビルOS側へ中継する実装例
